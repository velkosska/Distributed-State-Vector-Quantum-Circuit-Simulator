# Methodology (draft)

> Draft for the report. Values in ⟨angle brackets⟩ are filled from
> `results/*/*/meta.txt` and `results/summary/` once the final runs are in.
> Every number in the results section must come from a job whose `meta.txt`
> shows `git_dirty: no` and the commit tagged for the report.

## 1. What we measure

The simulator stores the state of *n* qubits as 2ⁿ complex doubles (16 B per
amplitude: 4 GiB at 28 qubits, 64 GiB at 32). Every gate is one streaming pass
over all or part of that vector with a handful of floating-point operations per
amplitude, so we expect run time to be bound by memory bandwidth on a node and
by network bandwidth between nodes. The experiments are designed to test that
expectation and to measure how far each backend (OpenMP, MPI, CUDA) is from the
corresponding hardware limit.

For every run the driver `qsim` reports

* **total time** `total_s`: wall time of the gate loop (`std::chrono::steady_clock`),
  excluding reading the circuit, allocating and initialising the state, and
  writing output;
* **time per gate** `total_s / gates_run`, the main quantity we compare across
  circuit sizes, because the number of gates itself grows with *n*;
* per gate (with `--timing`): the time, the bytes the kernel must read and
  write (`bytes_touched`, a traffic model: 2 × 16 B per touched amplitude), and
  the resulting **effective bandwidth** in GB/s;
* the **norm error** |⟨ψ|ψ⟩ − 1|; runs above 10⁻⁸ exit with an error and are
  dropped by the analysis.

## 2. Benchmark circuits

All circuits are generated by `src/tools/gen_circuits.py` with seed 1; the
generator is deterministic, so a circuit is identified by its command line,
which every job records in `meta.txt` together with a SHA-256 prefix of the file.

| Circuit | Construction | Gates at n = 28, seed 1 | Why |
|---|---|---|---|
| QFT | seeded R_Y layer on every qubit, then textbook QFT with final swaps | 448 | structured, many controlled-phase (diagonal) gates, O(n²) gates |
| Grover | ⌈n/2⌉+1 data qubits, V-chain ancillas for the multi-controlled Z, **one** iteration | 847 | long sequences of Toffoli-decomposed CX/T gates on few qubits |
| Random | depth 10; per layer a random 1-qubit gate on every qubit, then random pairs get a 2-qubit gate with probability 0.5 | 349 | unstructured mix of all gate types |
| Random, global fraction F | as random, but a share F of gate slots is placed on the p top ("global") qubits | 280 (n × depth, any F) | controls the amount of MPI communication (§6) |

One Grover iteration is enough for timing: the iteration is repeated
unchanged, so time per gate does not depend on the iteration count.
All backends are validated against Qiskit's `Statevector` before their timings are
used (`slurm/validate.sbatch`: QFT, Grover and random circuits, 2–20 qubits,
maximum amplitude error ≤ 10⁻¹⁰).

## 4. Running the experiments

All jobs are Slurm batch jobs; nothing is timed on login nodes. They share one
run harness (`slurm/lib/run_harness.sh`) so that every backend produces the same
records. For each job it writes `results/<experiment>/<jobid>/`:

* `meta.txt`: git commit and dirty flag (with the diff when dirty), SHA-256 of
  the binary and its CMake options, `module list`, allocated nodes, CPU model,
  caches and SIMD flags, GPU model, all `OMP_*`, `SLURM_*`, MPI and UCX
  environment variables, the generator command of every circuit and the exact
  command line of every run;
* `runs.csv`: one row per run, parsed from the `SUMMARY` line;
* `raw/`: per-gate timings and the full output of every run.

**Isolation.** Jobs request whole nodes (`--exclusive`), so no other job
competes for memory bandwidth. The OpenMP strong-scaling job compares
`OMP_PROC_BIND=close` and `spread` with `OMP_PLACES=cores`. MPI ranks use
`srun --cpu-bind=cores --exact`. The initialization loop uses the kernels'
static tile partition for NUMA first touch. Gates on high qubits can access
pages first touched by another worker.

**Repeats and statistics.** Each configuration is run **3 times** inside the same
job, on the same nodes, one after the other. We report the **median** and show
the **range** (min–max) as error bars. Medians are robust to a single disturbed
run; with three samples a standard deviation would not be meaningful. A
configuration whose range exceeds 10 % of its median is flagged by the analysis
and rerun before it is used.

## 5. Derived metrics

**Strong scaling** (fixed *n*, *p* workers = ranks × threads):
speedup S(p) = T(p₀)/T(p) · p₀ relative to the smallest worker count p₀ (normally 1),
efficiency E(p) = S(p)/p. Bounds use the extreme repeats
(T_min(p₀)/T_max(p) and T_max(p₀)/T_min(p)).

**Weak scaling** (one more qubit per doubling of *p*, so the amplitudes per
worker are constant): because the gate count also grows with *n* (QFT has
O(n²) gates), we compare **time per gate**, E_w(p) = t_gate(p₀)/t_gate(p).

**Amdahl fit.** We fit S(p) = 1/(f + (1−f)/p) by least squares. With
x = 1/p and y = 1/S the model is linear in f, y − x = f (1 − x), so
f = Σ(1−x)(y−x) / Σ(1−x)², with points at p = 1 excluded. We fit the median
speedups and, for an uncertainty band, the upper and lower speedup bounds.
We also report the Karp–Flatt metric e(p) = (1/S − 1/p)/(1 − 1/p). A constant
e(p) indicates a true serial part; a rising e(p) indicates overhead that grows
with p (bandwidth saturation, communication). For a memory-bound code we expect
the second, so f is a compact summary of the curve, not a literal serial
fraction of the code.

**Bandwidth and roofline.** The memory roof is the STREAM triad bandwidth
measured on the same nodes with the same pinning (`slurm/stream.sbatch`,
3 × 2 GiB arrays, best of 10, at 1, 2, 4, … threads). The arithmetic intensity
of each kernel follows from the same traffic model as `bytes_touched`
(complex multiply = 6 flop, add = 2 flop):

| Kernel | Gates | flop per amplitude of the state | bytes per amplitude | AI [flop/B] |
|---|---|---|---|---|
| dense 2×2 | H X Y RX RY U | 14 | 32 | 0.44 |
| diagonal, d₀ = 1 | Z S S† T T† P | 3 | 16 | 0.19 |
| diagonal | RZ | 6 | 32 | 0.19 |
| controlled 2×2 | CX CY | 7 | 16 | 0.44 |
| controlled phase | CZ CP | 1.5 | 8 | 0.19 |
| swap | SWAP | 0 | 16 | 0 |

All kernels sit far left of the ridge point (peak FLOP/s ÷ bandwidth, typically
5–20 flop/B), so the memory roof is the relevant limit and we report achieved
bandwidth as a fraction of STREAM. Two caveats: (1) the model counts only
touched amplitudes; for gates on low qubits the half or quarter that is not
touched shares cache lines with touched amplitudes, so real DRAM traffic is
higher and the effective bandwidth of Z/S/T/CZ/CP gates on low qubits is
underestimated; (2) STREAM does not count write-allocate traffic either, so the
two are comparable.

## 6. Communication sensitivity (MPI)

With P = 2^p ranks the top p qubits are global. `src/tools/analyze_circuit.py`
classifies each gate as *local*, *global but communication-free* (diagonal
gates, CX/CY with a global control) or *communicating* (dense 1-qubit gates on a
global qubit, CX/CY with a global target, SWAP between a local and a global
qubit), and reports the share of communicating gates, pct_comm. We run, at fixed
*n* = ⟨30⟩ and P = ⟨16⟩ (`slurm/sensitivity.sbatch`, qubit remapping off):

1. QFT, Grover and random circuits as they are, and
2. random circuits with global fraction F ∈ {0, 0.05, 0.1, 0.2, 0.3, 0.5, 0.75, 1}.

F is the requested share of gate slots on global qubits; pct_comm is what
actually communicates (roughly half of F, since diagonal and some controlled
gates need no exchange). We plot time per gate against pct_comm and fit
T = t_local · (local + global-free gates) + t_comm · (communicating gates) by
least squares; t_comm / t_local is the cost of one communicating gate in units
of a local gate. The benchmark circuits are then placed on the same axis.

## 7. Threats to validity

* **Three repeats** on one allocation capture run-to-run noise but not
  node-to-node variation; strong- and weak-scaling points at different node
  counts run on different nodes. We record the node list of every job.
* **Timer granularity**: per-gate timing adds ~µs per gate, negligible from
  ~20 qubits (≥ 1 ms per gate); below 16 qubits we use `--no-gate-timing`.
* **Turbo and frequency** are not fixed; `meta.txt` records the CPU model and
  maximum frequency.
* **Static communication analysis** assumes the identity qubit layout; with
  remapping on, the binary communicates less than pct_comm predicts.
